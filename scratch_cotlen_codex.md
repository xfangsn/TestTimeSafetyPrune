# Can scheme-A/BLADE control reasoning-chain length?

## Executive assessment

**Qualified yes for shortening; substantially less confidence for useful lengthening; and the broad activation-steering claim is already demonstrated by arXiv:2507.04742.** There is good evidence that a model can be moved into a more concise reasoning *mode*. That does not yet imply that scheme A's last-prompt-token contrast identifies the weights that causally govern the stopping decision, nor that zeroing/scaling those weights will give capability-preserving, bidirectional control.

The central distinction is between three different objects that can all correlate with token count:

1. a prompt-time **reasoning-budget/style plan** (brief, symbolic, expansive, explanatory);
2. a token-time **progress/termination hazard** (is the solution complete enough to emit `</think>`?); and
3. **reasoning competence** (hard or confused trajectories are often longer).

Scheme A is naturally suited to (1), whereas realized CoT length is largely the accumulated result of (2), with (3) as a severe confound. A sparse edit is scientifically interesting only if it changes (1) or (2) without damaging (3).

## 1. Construct and contrast design

### Recommended scheme-A contrast

For a strict test of the existing recipe, use **the same questions under paired short-budget and long-budget instructions**, with multiple paraphrases of each instruction and an identical chat-template suffix. For example:

- short: “Solve correctly, using only the indispensable reasoning steps. End thinking as soon as the answer is justified.”
- long: “Solve correctly and reason exhaustively, checking intermediate steps and alternatives before answering.”

Use a within-question difference before averaging:

\[
r_\ell = \frac{1}{N}\sum_q\left(h_\ell(q,I_{long})[-1]-h_\ell(q,I_{short})[-1]\right),
\]

and analogously define each writer's input shift \(\Delta\mu\). Ensure that `[-1]` is the same template/control token in both conditions, not the final lexical token of “briefly” versus “exhaustively.” Cross instruction paraphrases between calibration and evaluation so that the direction cannot succeed merely by recognizing a particular phrase. Balance topics and difficulty exactly because each question appears in both arms.

This is the cleanest option for testing **the claimed scheme-A locus**. It is still a direction for intended or expressed brevity, not necessarily for realized trajectory length. Instruction-following, natural-language verbosity, number of mathematical steps, and willingness to terminate remain bundled together.

### Why the other proposed contrasts are weaker or answer a different question

**Matched naturally short versus long correct CoTs on the same problem** are preferable for isolating realized behavior, provided both are generated by the same model, are correct, and use the same solution approach or matched semantic steps. They avoid difficulty and correctness confounds. But there is no nonzero last-prompt-token difference if the prompt is identical. One must teacher-force the completed trajectories and extract at aligned generated positions or at the terminal token. That becomes a trajectory-derived method, not strict scheme A. End-position representations are also confounded by absolute/relative position, EOS or `</think>` semantics, accumulated content, and surface style.

**Difficulty-graded prompts** should not be used to define the direction. Easy-versus-hard is primarily a task-content and competence direction. A resulting edit might shorten outputs by making the model fail earlier, or lengthen them by inducing confusion. Even a strong length effect would be uninterpretable.

A useful refinement for the trajectory contrast is to take one correct solution and produce meaning-preserving terse and verbose realizations with the same equations, conclusion, and step graph. Use same-model continuations or careful rewriting rather than “GPT-4o short versus target-model long” if construct purity matters. Then align by reasoning milestone and exclude EOS itself when estimating a direction. This better separates linguistic verbosity from computational depth, though it still does not give a prompt-boundary \(\Delta\mu\).

**Bottom line:** option (a) is the least confounded test of the *existing fixed-position recipe*; a tightly matched version of (b) is the best measurement of the *trajectory property*. Both are needed eventually, and agreement between their directions is itself a key result. Option (c) is not an acceptable primary construct.

## 2. Where the behavior probably lives

The most plausible mechanism is mixed rather than exclusively prompt-time or token-time.

At the prompt boundary, a reasoning model can plausibly establish a coarse policy: anticipated difficulty, desired proof detail, checking intensity, and approximate token budget. The model's responsiveness to “think briefly” and token budgets is evidence that such a state can exist. A prompt-boundary linear direction could therefore control style and an initial stopping prior.

But exact length is a sequential survival process. At every reasoning token the model implicitly chooses among continuing the current derivation, branching, verifying, restating, giving the answer, or emitting `</think>`/EOS. In a Qwen3-style thinking model, the logit margin

\[
\log p(\texttt{</think>})-\log p(\text{continue})
\]

and its hazard as a function of token index and solution progress are closer to the causal endpoint than the last prompt activation. A short solution occurs when this hazard rises earlier, not merely when a “concise” feature was decodable before generation.

There is an important nuance in BLADE's favor: although \(r\) and \(\Delta\mu\) are measured at the last prompt token, the edited `down_proj`/`o_proj` weights are used at **every subsequent decoding step**. Thus a prompt-derived score could find a global mode circuit whose edit later changes termination. The weakness is attribution: the score selects weights for what they write under prompt-boundary inputs, not for what they write near a mid-trajectory completion state. Decodability or steerability at the prompt position therefore does not establish that the selected entries implement the termination hazard.

The likely empirical pattern is asymmetric:

- Shortening can be achieved by raising the `</think>` hazard, suppressing branching/reflection language, or choosing denser symbolic expression.
- Lengthening is harder to make *useful*. Lowering the stop hazard can readily create padding, repeated checks, or loops. It does not automatically create additional valid computation or recover answers the baseline would miss.

Accordingly, layer selection should not be justified only by prompt-position ELS. ELS should be repeated on generated-token states, especially states 8–64 tokens before `</think>`, and compared with the prompt-selected layers. A prompt/mid-generation layer crossover would be evidence that “reasoning budget” and “stop now” are distinct regimes.

## 3. Feasibility of the sparse weight edit

Define the positive direction as **long minus short**. Then scheme A gives

\[
s_{ij}=[r_i W_{ij}\Delta\mu_j]_+.
\]

The intended prediction is straightforward: scaling selected weights to \(\alpha=0\) removes contributions that write the long-reasoning direction and should shorten CoT; \(\alpha>1\) should amplify them and lengthen it. A monotone response around the unedited \(\alpha=1\) would be compelling.

There are, however, at least four easy failure modes:

1. **Capability lesion:** the selected weights implement mathematical planning or attention to intermediate state, so `REMOVE` truncates correct derivations and lowers accuracy.
2. **Style-only edit:** outputs use fewer English tokens or denser equations but contain the same reasoning steps. This is useful compression, but it is not control of computational depth.
3. **Delimiter bias:** the edit mostly raises the `</think>` token logit. It shortens reliably, but behaves like a distributed early-exit hack and may terminate before proof completion.
4. **Degenerate amplification:** \(\alpha>1\) produces repetition, backtracking, or delayed termination rather than more effective deliberation.

Perplexity is necessary but not sufficient here. A 1% general-PPL change can coexist with a large lesion to a narrow mathematical circuit. The critical controls are:

- exact-answer accuracy at each induced length, stratified by baseline difficulty;
- paired analysis on examples the baseline gets correct (does shortening flip them wrong?) and wrong (does lengthening ever rescue them?);
- random-weight edits matched on layer, sparsity, weight magnitude, and edit norm;
- sign-flipped and shuffled-direction controls;
- prompt-only brevity, hard token truncation, and explicit early-exit baselines at matched token counts;
- delimiter validity, repetition rate, loop/censoring rate, and semantic step coverage;
- general PPL plus non-math capability benchmarks;
- held-out instruction paraphrases and held-out domains.

The strongest evidence would be an outward shift of the accuracy/compute frontier: at a fixed accuracy, fewer thinking tokens than the unedited model and prompt/early-exit baselines. “Shorter on average with unchanged aggregate accuracy” is weaker because gains on easy items can hide losses on hard ones. For amplification, extra length should improve accuracy or self-correction on a hard stratum; extra tokens alone are not a successful behavioral control.

There is also a deployment caveat to “on demand.” A permanently edited checkpoint is not per-request controllable unless the sparse delta is stored behind a scalar gate or models are swapped. A gated sparse delta can provide the requested \(\alpha\) knob, but the paper should describe it as a switchable sparse adapter/edit rather than implying that one static checkpoint accepts arbitrary user-time \(\alpha\).

## 4. Metrics: evaluate a frontier, not a token statistic

The primary plot should be **answer accuracy versus actual thinking tokens** over an \(\alpha\) or steering-strength sweep, with bootstrap confidence intervals and matched decoding seeds. Report the Pareto frontier against the unedited model, concise prompting, hard truncation, and the closest activation-steering baseline.

Measure at least:

- thinking tokens from `<think>` to the first valid `</think>`;
- tokens to first answer-bearing span, not just total response length;
- final-answer tokens separately;
- exact-match/pass@1 accuracy and, where necessary, a verified symbolic or judge-based score;
- median, mean, quantiles, and fraction censored at `max_new_tokens` (means are easily dominated by runaway traces);
- `</think>` survival curves and per-step termination hazard;
- accuracy conditioned on problem difficulty and on induced-length bins;
- repetition, branch/switch markers (“wait,” “alternatively,” restarts), and number of distinct valid reasoning steps;
- wall-clock latency and generated-token compute.

For a clean causal diagnostic, track the `</think>` logit rank/margin at matched semantic milestones under each intervention. If the edit changes token count but not termination hazard, it is probably altering expression density. If it shifts the hazard long before the solution is complete and accuracy falls, it is premature stopping. If it moves the hazard mainly after a valid solution is established, it is removing waste.

General capability preservation should include PPL and unrelated tasks, but the decisive preservation criterion is the **within-domain accuracy-at-matched-difficulty frontier**. Report short and long sides separately; bidirectionality in raw token count does not imply bidirectionality in useful reasoning.

## 5. Relation to arXiv:2507.04742

The paper is **Activation Steering for Chain-of-Thought Compression (ASC)**, submitted July 2025. This assessment is based on the v2 arXiv text and authors' repository, not recollection. It is a very close predecessor, but not the same method.

ASC samples 50 calibration questions, pairs a verbose CoT from the target reasoning model with a concise, math-centric CoT produced by GPT-4o, teacher-forces `question + CoT` through the target model, and takes a difference of mean **final-token/EOS residual activations** at one selected layer. At inference, it adds the concise-minus-verbose vector at that layer **at every decoding step**. It is training-free activation steering—not RL, fine-tuning, or merely a concise prompt. The paper chooses the layer empirically and proposes a KL-constrained rule for steering strength. It reports 33.8–67.43% token reductions on MATH500/GSM8K across DeepSeek-R1-Distill-Qwen-7B, DeepSeek-R1-Distill-Llama-8B, and QwQ-32B, with essentially unchanged aggregate accuracy; it also reports cross-task vector transfer. See the [arXiv paper](https://arxiv.org/html/2507.04742v2) and [authors' implementation](https://github.com/ArminAzizi98/ASC).

Consequences for novelty:

- The claim “CoT verbosity has a linear residual direction and can be shortened at inference time without retraining” is already covered.
- ASC is trajectory-derived (completed CoT/EOS) and injected throughout generation. Scheme A is prompt-derived and uses the direction plus writer-input shifts to select sparse weight entries. Those are genuine technical differences.
- BLADE could add a **sparse parameter-level mechanism**, zero per-token residual-injection overhead, ELS rather than a manually/empirically selected single layer, a continuous switchable weight-delta knob, and demonstrated **bidirectional** control. These are publishable deltas only if capability preservation and OOD transfer are stronger than ASC and if the long direction is productive rather than repetitive.
- BLADE-G's generic-importance penalty and matched random-edit controls could give better evidence that compression is localized rather than mild damage.

ASC also leaves openings. Its contrast changes generator identity (GPT-4o short versus target-model long), linguistic style (math-centric versus English-heavy), and sequence length at the EOS extraction position. Thus its vector need not be a pure length direction. It reports compression rather than demonstrated reverse/elongation control, and its per-step KL bound is local to an output distribution; it does not by itself guarantee a small whole-trajectory distribution shift or preserved reasoning competence. Its main table gives average tokens and aggregate accuracy at selected settings, not a full accuracy/length Pareto analysis across difficulty. These limitations motivate a cleaner BLADE study, but they do not erase ASC's priority on activation-based CoT compression.

## 6. Verdict and the single decisive first experiment

### Verdict

This is a **promising but narrowed extension**, not a fresh demonstration that reasoning length is linearly controllable. I would assign higher prior probability to capability-preserving shortening than to capability-preserving, useful lengthening. I would also expect a trajectory-derived, every-token intervention to outperform a one-time prompt-boundary intervention. The strict scheme-A sparse edit is therefore a meaningful empirical question, not a safe extrapolation from the uncertainty result.

A positive result requires all three of the following:

1. held-out, monotone, bidirectional movement of *thinking* length around \(\alpha=1\);
2. a better accuracy/length frontier than prompting, truncation, random edits, and ASC-style activation steering; and
3. evidence that amplification adds productive computation and that removal eliminates redundant computation rather than reasoning ability.

If only the short side works, the honest contribution is “sparse weight editing for CoT compression,” not general bidirectional control of reasoning-chain length. If an ASC-style trajectory direction works but the prompt-derived direction does not, the conclusion is that length is steerable but the established fixed-position scheme-A construct is at the wrong locus.

### Most decisive first experiment: a causal locus screen before any large weight-edit campaign

Run one preregistered, paired experiment on Qwen3-8B:

1. Use 128 calibration math problems, each with short/long instructions and 8 balanced paraphrase pairs; keep the final chat-template token identical. Extract prompt-boundary \(r_\ell^{prompt}\) and run ELS. Separately construct same-question, correct, semantically matched short/long trajectories and extract an ASC-style \(r_\ell^{traj}\) near completion (excluding the literal delimiter where possible).
2. On disjoint MATH500 problems under a **neutral prompt**, sweep signed steering strength for each direction under three schedules: last-prompt-token only, every thinking token, and only after token 64. Use fixed sampling seeds.
3. Plot accuracy versus median thinking tokens, plus `</think>` hazard and censoring, for all six direction/schedule combinations. Include random and sign controls and concise prompting at matched length.

Preregister success as a monotone signed change of at least roughly 25% in median thinking tokens in both directions, with no more than a 1 percentage-point accuracy loss on the baseline-correct subset and no increase in invalid/looped completions. The exact thresholds can be adjusted to available power, but they must be fixed before inspection.

This experiment resolves the load-bearing uncertainty cheaply. If the **prompt-derived direction works from the prompt-only schedule**, scheme A has found a genuine pre-commitment signal and a BLADE weight edit is well motivated. If it works only when injected every step or late, length control is mainly a trajectory/termination phenomenon; recompute BLADE scores on generated-token completion states rather than claiming the unchanged scheme-A recipe. If only the trajectory-derived direction works, reproduce ASC but do not proceed with prompt-position BLADE. If neither works without accuracy loss, sparse length editing is likely to be capability damage dressed up as compression.
